## 1. What to build
### 1.1 `v0/system.py`
`build_v0(bed, tuning_dir="results/m1/tuning")` returns the V0 arm (an `m1.arms.Arm`), `arm_id` "V0", for the beds `B3seq`, `B3mix`, `B3drift` (the 7-domain real-text beds of `m1.beds.build_bed(name, 22, seed)`; text embeddings are cached under `results/unimoe/emb`, set `HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1`). It refuses other beds with a clear message (UniPool candidates are B3 only). `describe_v0()` returns the plain list of parts (encoder, pool, head, flag, what is off) for the report. **Test:** `build_v0(bed).config()` equals the config of `build_arm("H_ULDA", bed, tuning=...)` except the arm id.

### 1.2 `v0/demo.py` (`python -m v0.demo --schedule seq|mix|drift --seed 800 --out DIR [--max-phases N]`)
Runs the stream phase by phase with the same loop and batch size as `m1.cell.execute_cell` (read it; `bed.walk_full(64)`). After every phase it records, for V0: the accuracy on the test set of every regime seen so far and their mean; forgetting up to now (`growmoe.metrics.accuracy_stats`); number of experts (`arm.describe()`); memory bytes (`arm.memory_bytes()`); update seconds so far; the **unknown flag**: the share of the known test examples that `predict(...).unknown` marks unknown (false new) and the share of the stream's out-of-domain examples (`bed.stream.ood`, a dict of name to tensor; read `unimoe/suite.py` and `unimoe/domains.py:ood_sets`) marked unknown; and at the end the AUROC of the novelty score (`Prediction.p_nov`) between known test examples and each out-of-domain set (a rank AUROC with correct tie handling, written by you and tested on hand-made scores: perfect separation gives 1.0, identical scores 0.5). Also the answer latency at batch 1 and 32 of V0 and of each comparator (`costlab.timing.time_callable`).
**Comparators** on exactly the same data in the same order, each with its frozen tuned entry from `results/m1/tuning/B3seq.json` (read only): same-memory replay network (arm `A3`, budget = V0's final memory bytes from pass 1), kNN with the same memory (`A7`), streaming LDA (`A5a`). Build them with `m1.arms.build_arm`. V0 is run first to get its final memory; the comparators then run the stream and are evaluated at the same phase boundaries. If a comparator beats V0 at the end on the mean accuracy of all regimes, the summary says so in a plain generated sentence; no comparator is dropped to look better.
**Outputs under `--out`:** `record.json` (every number above, every arm's `config()`, seed, schedule, commit from `costlab.env.environment()`, pinning, the label "DEMONSTRATION, NOT A RESULT"), `table.md` (one table per phase boundary), `figure.png` (small multiples, one y-axis per chart, thin marks, a legend where there are two or more series, colour-blind-safe colours from `m1.report.ARM_COLORS`, titles built from the generated numbers: mean accuracy over seen regimes against phase for V0 and the three comparators; experts of V0 against phase; memory in bytes of all four against phase; the two unknown-flag rates of V0 against phase; matplotlib only), `summary.txt` (plain English, every number generated, includes V0's cost next to its behaviour and the AUROC with the sentence that a value near 0.5 means the flag does not work). Atomic writes (write to a temporary file, then rename). Idempotent: an existing complete record for the same arguments and code is reported and skipped.

### 1.3 `v0/report.py`
`python -m v0.report --runs DIR1 DIR2 ... --out OUT`: merges several demo outputs (schedules, seeds) into one table and one summary figure. Labels every table DEV (development seeds only) and refuses report seeds (810-829). On hand-made fixtures labelled SYNTHETIC it must run and the label must appear in the first line.

### 1.4 Tests (`tests/v0/test_v0.py`, module-scope autouse fixture pinning to logical processors 8 and 10 with 2 threads, whole file under 2 minutes)
(a) `build_v0` config equals `H_ULDA` config; refuses B1 and B2. (b) A demo with `--max-phases 3` writes all four files and the record carries the demonstration label. (c) **The assembly check:** on `B3seq`, seed 800, the full-stream final accuracy and per-regime accuracy of V0 in the demo equal those of `m1.cell.execute_cell(bed, "H_ULDA", profile="det", tuning=...)` exactly (this is the defence against a wrong join; if they differ, find out why and say it in the result file, do not loosen the test). (d) Comparators see the same batches in the same order as V0 (compare a hash of the batch labels) and the replay comparator's memory is within 5 % of V0's final memory. (e) The AUROC function on hand-made scores. (f) The report on SYNTHETIC fixtures. (g) Re-running a finished demo skips it.
