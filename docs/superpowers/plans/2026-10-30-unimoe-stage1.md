# UniMoE Stage 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans (inline). Progress ledger: `research/unimoe/PROGRESS.md` (a task is done when its line is there). Test first for every module.

**Goal:** One combined dynamic MoE (growmoe pool with every learned stage on, optional vertical stack, Router layer) trained on mixed real streams, with an evaluation harness and a deep-analysis report.

**Architecture:** new package `unimoe/` over `growmoe/` (not edited). `frontends` (shared unit sphere) -> `domains` (real data) -> `suite` (streams S-seq / S-mix / S-drift with test sets, OOD sets) -> `systems` (UniMoE variants, baselines) -> `runner` (test-then-train, phase snapshots, logs) -> `analysis` (metrics A-K of the design) -> `report`.

**Tech:** Python 3.12, torch (RTX 3060, one GPU job at a time), sentence-transformers (local MiniLM), pandas/parquet from the local HF cache. No downloads.

**Spec:** `docs/superpowers/specs/2026-10-30-unimoe-design.md`

## Global Constraints
- `growmoe/` is not edited (NG1); patches live in `unimoe/` and are recorded.
- Seeds: dev 500-504 only; 600-604 reserved, unspent. All results are dev, exploratory.
- Predictions are written to `research/unimoe/PROGRESS.md` BEFORE each full run; no bar changed after a number.
- Every run cell is checkpointed (atomic JSON/npz, code stamp) and idempotent to relaunch (daily power cuts); one GPU job at a time.
- Pool seed = stream seed + 7. Baselines get equal memory and a tuned step count each.
- Numbers in reports are generated by script, never typed.

## Review Focus (input classes the tests must pin)
- A domain with fewer samples than asked (SVAMP) must not crash or duplicate samples across train and test.
- Label blocks of different domains must never overlap (global label space), arithmetic digit labels are shared by design within their block.
- A regime never seen yet must report accuracy at chance, not NaN, in the accuracy matrix.
- Stream determinism: same seed, same stream; different seed, different order.
- No ground truth reaches a pool: runner passes only (x, y).
- A cached cell with a different code stamp must be recomputed.

## Tasks

### T1 frontends (`unimoe/frontends.py`, `tests/unimoe/test_frontends.py`)
Produces `SphereFrontend(d=128, seed=0, cache_dir=None, encoder=None)`; `.text(texts) -> Tensor (N,d)` unit (frozen MiniLM -> fixed random projection seed 0xE1B, the HybridFrontend's map, so results compare with earlier work; embeddings cached on disk by text hash); `.digits(arr) -> Tensor (N,d)` unit, zero-padded. Tests: unit norm and shape; determinism; cache hit makes no encoder call; the projection keeps cosine order (rank correlation > 0.8 with 384-d cosines on a toy set); digits pad and normalise.

### T2 domains (`unimoe/domains.py`, `tests/unimoe/test_domains.py`)
Produces `Domain(name, kind, x_train, y_train, x_test, y_test, class_names, groups, meta)`, `load_domain(name, fe, seed, cap_train, cap_test)`, `group_classes(class_vectors, n_groups, seed)`, `ood_sets(fe, seed, n)`. Domains: banking, agnews, newsgroups, emotion, sst2, svamp, arith. Tests: `group_classes` partitions and is deterministic; each real loader gives labels inside range, groups partition classes, test texts disjoint from train texts, sizes capped; SVAMP smaller than the cap works.

### T3 suite (`unimoe/suite.py`, `tests/unimoe/test_suite.py`)
Produces `Regime`, `Phase`, `UStream`, `build_suite(schedule, domains, seed, fe, ...)`, global label offsets, n_classes. Schedules `seq` (domains in a seed-permuted order, regimes within a domain consecutive, revisits at the end), `mix` (all regimes interleaved i.i.d. in K phases), `drift` (regime weights drift in time). Tests: label blocks disjoint; every regime has a test set; first-visit flags right; seq phases single-regime, mix phases multi-regime; determinism; algo view exposes only (x, y).

### T4 systems (`unimoe/systems.py`, `tests/unimoe/test_systems.py`)
Produces `make_system(name, d, n_classes, seed, recipe, mem_bytes)` for `shipped`, `U-real`, `U-stack`, `U-recipe` and baselines `finetune`, `replay_eqmem`, `knn_eqmem`, `lda`, `joint_offline`, `oracle_experts`, plus `SYSTEMS` registry. Tests: each factory returns an object with observe/predict/summary/events; configs have the declared switches (U-real: set gate on, persistence 2, gap growth; shipped: defaults); a tiny stream smoke for each.

### T5 runner (`unimoe/runner.py`, `tests/unimoe/test_runner.py`)
Produces `run_system(make_pool, stream, seed, batch_size) -> RunRecord` (accuracy matrix per phase, per-sample train and final-test logs, phase snapshots of structure and cost, OOD novelty per phase, oracle-routing accuracy for pools that expose experts) and `run_cell(...)` with stamped atomic caching. Tests: test-then-train order (predict before observe), unseen regime accuracy is chance not NaN, cache reuse and stamp invalidation, no ground truth in the pool call (spy pool).

### T6 analysis (`unimoe/analysis.py`, `tests/unimoe/test_analysis.py`)
Produces functions for battery A-K: performance and intervals, continual metrics (reuse `growmoe.metrics.accuracy_stats`), structure (experts vs regimes, purity, NMI, false and missed spawns), routing gap, novelty (false-novel, AUROC on OOD), cost, representation diagnostics, failure taxonomy, ablation deltas. Tests on synthetic logs with known answers.

### T7 report (`unimoe/report.py`)
Generates the markdown and figures from RunRecords (accuracy matrix heatmap, expert count and event timelines, routing confusion, per-domain bars); numbers copied from records. Test: renders from synthetic records, every section present.

### T8 experiment driver and first full run (`unimoe/experiment.py`)
CLI over seeds, schedules, systems; per-cell cache; writes `results/unimoe/`. Step zero: the step grid for each trainable arm on seed 500 (tune each arm), then predictions written, then the full dev run (seeds 500-502 first, 503-504 after), report v1.

### T9 deep analysis and findings
Ablations (U-real minus one component), robustness (orders, schedules), failure analysis, representation diagnostics; the ranked shortcomings list; notebook entry, claims, failures; design note; memory.
