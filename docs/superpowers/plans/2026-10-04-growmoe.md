# GrowMoE Implementation Plan

> **For agentic workers:** executed inline in one session (no subagents), test-first. Each task: write tests → run, watch them **fail for the right reason** → implement minimally → run, watch them pass → run the whole `tests/growmoe` suite. Steps use checkbox syntax. *Deviation from the template, on purpose:* the plan gives exact signatures, formulas and the assertions each test must pin down; the production code is written at execution time, test-first, rather than pasted here twice.

**Goal:** Build, test and compare three self-growing, novelty-aware MoE architectures (A calibrated-phylogenetic, B Bayesian-nonparametric/CN-DPM-style, C key-addressed delta/"DNA") with expert-, layer- and system-level scaling, on local data only.

**Architecture:** Shared infrastructure (frontend, conformal gate, vMF signature, residual-MLP experts, growth policy, telemetry, metrics, streams, baselines, benchmark runner) + three pool implementations behind one `ContinualPool` protocol; Phase 2 stacks pools vertically; Phase 3 adds columns and clade routing. Every threshold is an error rate or a tolerance with units.

**Tech Stack:** Python 3.12, PyTorch 2.6 (CPU), NumPy 2.2, SciPy 1.17, scikit-learn 1.5 (bundled datasets only), pytest 9. No new dependencies, no downloads.

**Spec:** `docs/superpowers/specs/2026-10-04-growmoe-design.md` (research: `research/DYNAMIC_MOE_RESEARCH_AND_DESIGN.md`)

## Global Constraints

- Nothing under `ishmn/` is modified; new code lives in `growmoe/`, tests in `tests/growmoe/`.
- **Test files are named `test_gm_*.py` and `tests/growmoe/` has NO `__init__.py`** (an `__init__.py` would make pytest import tests as a top-level `growmoe` package and shadow the real one).
- Python `hash()` is never used; all randomness via explicit seeded `numpy.random.Generator` / `torch.Generator`; results identical across processes.
- Algorithms never read ground truth (regime ids, first-visit or outlier flags).
- Local data only: scikit-learn bundled datasets, Python stdlib text/code, synthetic.
- Reported claims use ≥ 10 seeds, mean ± 95 % CI, paired tests; hyper-parameters tuned only on development streams, then frozen; numeric grading only.
- Run tests with `python -m pytest tests/growmoe -q` from `D:\spherical_hyperspace_memory`.
- No git commits unless the user asks; each task ends with a **checkpoint** (suite green) instead.

### Task 2: Frontend (type-agnostic)
**Files:** `growmoe/frontend.py`, `tests/growmoe/test_gm_frontend.py`.
**Produces:** `HashFrontend(d=128, seed=0, max_len=4096, ngram=(1,2,3), salt_by_shape=False)`; `.encode_numeric(arr) -> Tensor(B,d)`; `.encode_bytes(items) -> Tensor(B,d)`; `__call__(items)` dispatching on type.
Numeric: flatten each item to length L; bucket `h(i)` and sign `s(i)` from a seeded table; `z[h(i)] += s(i)·v_i`; L2-normalise (all-zero → fixed unit vector). Bytes/str: n-gram hashed with `zlib.crc32`, counts → `log1p` → L2.
- [ ] Tests: unit norm (atol 1e-5); identical output for two fresh instances **and across processes with different `PYTHONHASHSEED`** (subprocess); accepts `(B,64)`, `(B,8,8)`, `(B,13)`, list of ragged arrays, and `list[str]`/`list[bytes]`; cosine preservation for random sparse vectors (95th percentile of `|cos_z − cos_x| < 0.2` at d=128, L=64); different seeds → near-orthogonal encodings of the same input (|cos| < 0.35); with `salt_by_shape=False` a 13-vector and the same values zero-padded to 64 encode identically; global input scaling does not change the output.
- [ ] Red → implement → green → checkpoint.

### Task 3: Conformal p-values and BH
**Files:** `growmoe/conformal.py`, `tests/growmoe/test_gm_conformal.py`.
**Produces:** `conformal_pvalues(cal: Tensor[n], test: Tensor[m]) -> Tensor[m]` (`(1 + #{cal ≤ test})/(n+1)`, low score = novel); `benjamini_hochberg(p: Tensor[m], q: float) -> BoolTensor[m]`.
- [ ] Tests: iid cal/test from N(0,1) → `P(p ≤ α)` within binomial 3σ of α for α ∈ {0.01, 0.05, 0.1} (20,000 draws); shifted test (mean −3) → power > 0.9 at α = 0.05; BH on 80 % nulls / 20 % shifted: empirical FDR ≤ q + 0.02 over 500 repetitions; ties handled (`≤`); `n = 0` raises `ValueError`.
- [ ] Red → implement → green → checkpoint.

### Task 4: vMF signature
**Files:** `growmoe/signature.py`, `tests/growmoe/test_gm_signature.py`.
**Produces:** `log_vmf_norm(d, kappa) -> float` (via `scipy.special.ive`); `VmfSignature(d, max_protos=256, kappa_grid=(2,4,8,16,32,64,128,256), seed=0)` with `update(u)`, `fit()`, `score(u)` (= `lse_j κ⟨p_j,u⟩ − log n`), `logpdf(u)` (adds `log_vmf_norm`), `pvalue(u)`, properties `n`, `kappa`, `cal_scores`, and `merge_from(other)`.
- [ ] Tests: `log_vmf_norm(3, κ) ≈ log(κ/(4π sinh κ))` for κ ∈ {1, 5, 20}; density integrates to 1 on S² (quadrature on a grid, tolerance 1e-3); tight cluster selects larger κ than diffuse cluster; two vMF clusters at d = 128 → AUROC(score in-cluster vs out-of-cluster) > 0.99; held-out same-distribution samples: `P(p ≤ α) ≤ α + 0.02` for α = 0.05; reservoir after streaming 10 k points keeps ≤ `max_protos` and prototype arrival order is uniform (mean arrival rank within 10 % of N/2); two shuffles of the same stream choose κ within one grid step; `pvalue` is monotone in `score`.
- [ ] Red → implement → green → checkpoint.

### Task 5: Residual-MLP expert with growth
**Files:** `growmoe/experts.py`, `tests/growmoe/test_gm_experts.py`.
**Produces:** `MLPExpert(d_in=128, hidden=128, depth=1, n_classes=64, seed=0)`: `forward(u) -> logits` (unseen classes masked to −1e9), `mark_seen(y)`, `loss(u,y)`, `num_params()`, `clone()`, `widen(k, rng=None)` (new hidden units in every block, zero outgoing weights), `deepen(rng=None)` (new block with zero output), `inherit(rho, sigma, rng) -> MLPExpert` (re-draw `round(rho·H)` hidden units per block with the parent's weight statistics, add `N(0, sigma·std)` noise); `train_step(u, y, opt, replay=None, project=False)` implementing optional A-GEM projection.
- [ ] Tests: logits shape and masking; toy 3-class problem reaches > 0.95 accuracy; `clone` outputs identical; `widen(16)` and `deepen()` leave outputs unchanged (atol 1e-6) and increase `num_params`; `inherit(0, 0)` identical, `inherit(1.0, 0)` differs on > 99 % of inputs; re-drawn hidden-unit fraction equals `round(rho·H)/H`; after one optimiser step the new W2 columns of a widened expert are non-zero (new capacity is trainable); with `project=True` and conflicting replay gradient the update has non-negative dot with the replay gradient.
- [ ] Red → implement → green → checkpoint.

## Phase 1 — three pools on single-layer streams

### Task 13: Architecture A — PhyloMoE (core lifecycle)
**Files:** `growmoe/pools/phylo.py`, `tests/growmoe/test_gm_phylo.py`.
**Produces:** `PhyloMoE(cfg: PhyloCfg)` (protocol-conforming). Algorithm (spec §5): bootstrap → conformal gate (`p_nov = max_k p_k`, BH at `q`) → train routed experts (+ replay, optional A-GEM) → probation pool → similarity-graph clustering (τ_in from known data's NN-similarity quantile) → evidence test `Σ[log f_{C,LOO} − max_k log f_k] > log(1/α_spawn)` → best parent by affinity → interference probe (extend vs spawn) → `inherit(ρ_max·(1 − affinity), σ)` → infant protection → competence monitor → merge by distillation → archive/revive. Sub-steps, each with its own red→green:
- [ ] 13a Bootstrap: first `m_min` samples create the first expert from scratch; no spawn before that. Test: stream of one regime → exactly 1 expert.
- [ ] 13b Gate and known/novel split: samples from a seen regime are assigned (not pooled) with empirical false-novelty ≤ 2 × q on 5 seeds; samples from an unseen regime are flagged with power > 0.9 once calibrated.
- [ ] 13c Probation: 50 isolated outliers across 50 batches → 0 spawns; one coherent burst of 3 × `m_min` → exactly 1 spawn; the pool never exceeds `pool_cap`; entries older than `pool_ttl` are dropped.
- [ ] 13d Spawn + DNA: the child's `parent` is the max-affinity expert; `ρ` shrinks as affinity grows (monotone, tested on constructed affinities); lineage event recorded with novelty statistics; child outputs equal parent's when `ρ = σ = 0`.
- [ ] 13e Interference probe: constructed aligned task → `extend`; conflicting task (permuted labels on near inputs) → `spawn`; the extended parent's replay loss rises by ≤ `δ_forget + tol`; flipping `δ_forget` flips the decision.
- [ ] 13f Infant protection and maturity: infants accept samples at relaxed level and use `infant_lr_mult`; after `infant_steps` they mature; a regime arriving in 5 consecutive classes does **not** spawn 5 experts.
- [ ] 13g Competence-driven adaptation: same inputs, remapped labels (S7 without ctx) → monitor alarms, pool spawns; stationary stream → no alarm.
- [ ] 13h Merge (distillation) and archive/revive: two duplicate experts merge with probe accuracy change ≤ `δ_merge`; a dormant expert is archived, still gates, and revives when its regime returns (revisit routes to the original id).
- [ ] 13i Unlabeled mode (`y=None`): regime discovery on a 3-regime stream yields 3 signature-only experts, no training calls.
- [ ] 13j Determinism: same seed → identical event log; a `ContinualPool` API test asserts there is no parameter for ground truth.
- [ ] Checkpoint after each sub-step; at the end run the **Phase-1 mini-integration** (3-regime toy stream: 3 experts, final accuracy ≥ 0.9, revisit does not spawn).

- [ ] Tests: VAE ELBO improves with training on a vMF cluster and is higher in-cluster than out-of-cluster; STM below `n_stm` never spawns; ≥ `n_stm` coherent rejected samples spawn exactly one scratch expert; τ_B monotonicity (larger τ_B ⇒ fewer spawns on the same stream); protocol conformance; deterministic.

### Task 16: Architecture C — Keyed Delta-MoE
**Files:** `growmoe/delta.py`, `growmoe/pools/keyed.py`, `tests/growmoe/test_gm_delta.py`, `tests/growmoe/test_gm_keyed.py`.
**Produces:** `DeltaExpert(base: BaseNet, rank=16, lineage=[])` with effective weights `W = W_base + Σ_{a∈lineage} A_a B_aᵀ + A B ᵀ`, `fork() -> DeltaExpert` (child lineage = parent lineage + frozen snapshot of parent's own delta; own delta zero-init), `rank_up(k)`, `add_block()`, `flatten(r)` (truncated SVD to rank r), `merge_siblings(other)`; `KeyedDeltaMoE(cfg: KeyedCfg)`: key activation z-score gate, STM spawn rule, fork-from-nearest-key, sibling delta merge, archive/revive.
- [ ] Tests: `fork` is function-preserving (atol 1e-6) and later changes to the parent do **not** change the child's output (copy-on-write); `rank_up` and `add_block` function-preserving; `flatten` approximates within a stated relative error on a rank-≤ r delta sum; sibling merge keeps probe accuracy within tolerance; memory per expert ≤ 40 % of an equivalent `MLPExpert`; key gate separates two regimes (AUROC > 0.9); protocol conformance; deterministic.
- [ ] Red → implement → green → checkpoint.
