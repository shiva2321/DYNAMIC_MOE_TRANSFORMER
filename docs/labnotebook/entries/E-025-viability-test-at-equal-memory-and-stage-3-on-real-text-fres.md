## Question
At the SAME memory, does the growing pool still beat a single network and a lookup on streams where every regime has its own rule, and does the gain grow with the number of regimes? And does the amended stage-3 gate repair the real-text failure of M5-B (E-024 follow-up)?

## Why we asked it
The user asked whether GrowMoE is viable. The earlier comparisons were not equal-memory (the pool used 1.4x the best single network's bytes in M2-A, E-015), the single-network width grid stopped at 4096, and the only real-text stream (M5-B) was a failure (pool 71.8 against replay 83.7, kNN 87.3).

## Prediction (written BEFORE the numbers)
Shootout (header of `shootout.py`): pass line = pool beats the best same-memory replay cell and the same-memory kNN by >= 5 points at N = 100 AND uses <= 1/3 of the best replay cell's multiply-adds per prediction. M5-D (header of `run_m5d_fresh.py`): on fresh seeds 80-84, stage 3 beats today's pool by >= 5 points on >= 4 of 5 seeds AND the stage-3 pool is within 5 points of the replay network that gets its bytes.

## Method (how)
Streams: `function_regimes` with N = 10, 30 and 100 hidden-rule regimes (seeds 100-104, 100-104, 100-102); banking77 class-incremental with the frozen MiniLM hybrid frontend (`HybridFrontend`, d = 128), dev seeds 100-102 and fresh seeds 80-84. Memory = 4 x parameters + 4 x d x stored vectors (the project's accounting, includes signatures, replay buffers and source windows). Arms: pool (product defaults, 5 steps; 20 steps on banking77; stage-3 arm with `set_gate=True`, persistence 2), replay network with the pool's bytes (grid of widths and 5 / 20 steps; the best cell is reported, chosen on the evaluation seeds, which favours the baseline), kNN with the pool's bytes and with everything stored, oracle-routed experts, joint single network (reference). Control: joint single network with 20 / 100 / 400 training steps per observe.

## Interpretation (what we understood, and on what basis)
Plain words: on streams made of different rules, the pool keeps old tasks and its accuracy does not fall as tasks accumulate, while a single network of the same memory gets worse with every task and no amount of extra training (the control) lifts it; a lookup cannot do these tasks at all. The pool also needs far fewer multiply-adds per answer, because only one small expert runs and the shortlist keeps the gate cheap. On real text categories the picture is different: with the stage-3 batch gate the pool is no longer broken (it finds 3 to 6 experts instead of 1 to 3) and sits level with a replay network of the same memory, but a plain nearest-neighbour lookup is still about 4 points ahead, and the pool needs more memory than the 3,000-sample stream itself.
Technical statement: measured, synthetic family: pool - best equal-memory replay cell = +14.1 [+12.4, +15.9] points at N = 10 (5 seeds) and larger at 30 and 100 (see tables); measured, real text: +7.0 [+2.0, +11.9] over today's pool on fresh seeds, within 1.2 points of the best same-memory replay net. Assumed: that function-regime streams represent a real class of problems (computed rules that differ by context); no real dataset of that class was tested.

## Caveats and what went wrong
- The synthetic family is built so that a lookup cannot win; it shows what the mechanism can do, not that real problems look like this.
- The baselines' best cell was chosen on the evaluation seeds (conservative for the claim); the replay grid has widths up to 16384 and steps 5 / 20 only; more steps were not tried for N = 100.
- At N = 30 the pool already uses as many bytes as the raw stream (12.0 MB against 13.1 MB): it is not memory-efficient compared with storing the data, it wins where storing the data does not work.
- The M5-D prediction failed in its first part (3 of 5 seeds reached +5; seed 80's own pool was already at 81.1 %). Reported as it is.
- Dev-seed numbers (shootout, M5-C) are exploratory; seeds 80-84 are used up by M5-D; the stage-3 confirmatory seeds 60-79 are untouched.
- A first draft of the demo labelled a simple oracle-routed arm "the best any routing could do"; the pool beat it (its experts use a replay recipe), so the label was wrong and the row was removed.

## Consequence
Stage 3 continues on the pre-registered path (dev step running; prereg and the confirmatory run on seeds 60-79 need the user's go). The open gap is a real dataset where the rule differs by context. Window size of the set gate (memory) is a later tuning (Q-19). A runnable demo was added: `demos/demo_growmoe_continual_learning.py`.
