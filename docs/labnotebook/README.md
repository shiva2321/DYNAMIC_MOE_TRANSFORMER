# Lab notebook: the working record of the project

Started 2026-10-12. This is the one place that says **what we did, how, why, what came out, what we understood and on what basis**, for successes and failures alike,
so that any claim can later be put in a paper together with the proof behind it. It does not replace the primary records (pre-registrations, generated result files,
reports, code, git history); it points at them, explains them and ties them together.

## 1. How it is organised

| File | What it holds |
|---|---|
| `entries/E-NNN-*.md` | One entry per investigation, experiment, audit, design step or process event, in time order. Each entry follows `templates/ENTRY.md`. |
| `INDEX.md` | Generated table of all entries (`tools/labnb.py index`). |
| `CLAIMS.md` | **The claims register**: every statement we might want to publish or rely on, its status (SUPPORTED, REFUTED, OPEN, ...), evidence grade, entries and limits. The backbone of any paper. |
| `FAILURES.md` | Failures, negative results and our own mistakes, each with the lesson. Kept on purpose: they are results too. |
| `DECISIONS.md` | Why we chose what we chose: the decision, the alternatives, the basis. |
| `OPEN_QUESTIONS.md` | What we do not know yet and the cheapest experiment that would tell us (the "will do" list). |
| `PAPER_NOTES.md` | Candidate papers: outline, which claims they rest on, what evidence exists, what is missing. |
| `GLOSSARY.md`, `REFERENCES.md` | Terms (plain words first) and the literature, marked by how much of it we actually read. |
| `evidence/SOURCES.txt`, `MANIFEST.md` and `MANIFEST.json` | The list of evidence files and a **generated manifest with sha256, size and last commit** of each (`tools/labnb.py manifest`). |
| `tools/labnb.py` | `new`, `index`, `manifest`, `verify`. |

## 2. Rules (each one exists because we broke it once)

1. **Numbers are copied by script from generated files, never retyped; result files are never edited by hand.** If a number is wrong the generator is fixed and re-run, and the entry says so.
2. **Record the prediction before the numbers.** A pre-registration (bars, expected outcomes, seeds, budgets) is written and hash-frozen before the first test seed runs; its result is reported as PASS or FAIL against it, including "AGAINST expectation".
3. **Dev seeds (100 and up) are for tuning and choosing bars; test seeds are never used to choose anything.** Used test seeds are listed in `DECISIONS.md` and never reused for a new claim.
4. **Failures are entries, not deletions.** A refuted claim stays in `CLAIMS.md` as REFUTED with the entry that refuted it. A mistake of ours goes to `FAILURES.md` with the lesson.
5. **Entries are append-only.** A later finding that changes an earlier one is a new entry that says "supersedes E-NNN" (and the old entry gets a one-line pointer); the old text stays readable.
6. **Say what is measured and what is assumed.** Every claim carries an evidence grade (section 3). Literature we only read at abstract level is marked `L`; things recalled but not rechecked are `R`.
7. **Say who did it.** User decision, Claude (designer / reviewer / light implementer), Gemini (implementer), and whether the result was re-run by someone else.
8. **Controls and baselines belong next to the claim**: a tuned replay network, kNN, an oracle, an isolating control. A number without its control is not recorded as a finding.
9. **Reproducibility data**: commit, seeds, budgets, the exact command. The environment is in section 5.

## 3. Evidence grades

| Grade | Meaning |
|---|---|
| **A** | Pre-registered, fresh test seeds, script-generated verdicts, reproduced (re-run by the reviewer or regenerated byte for byte). Safe to publish with its limits. |
| **B** | Script-generated and multi-seed, but exploratory (dev seeds, not pre-registered) or only partly reproduced. Good for choosing a direction, not for a headline claim. |
| **C** | A single run, a hand check or a reviewer's spot check. Anecdotal until repeated. |
| **L** | Literature, read at abstract level only. |
| **R** | Recalled, not rechecked. |
| **H** | Hypothesis. Nothing measured. |

Statuses used for claims: SUPPORTED, REFUTED, PARTIAL, OPEN (not yet tested), UNVERIFIED (claimed by someone, never audited), SUPERSEDED.

## 6. How to add to the notebook

```
python docs/labnotebook/tools/labnb.py new "Short title" --type experiment --track G   # scaffolds entries/E-NNN-short-title.md
# fill it in; add new evidence globs to evidence/SOURCES.txt; add/update rows in CLAIMS.md, FAILURES.md, DECISIONS.md, OPEN_QUESTIONS.md
python docs/labnotebook/tools/labnb.py index
python docs/labnotebook/tools/labnb.py manifest
python docs/labnotebook/tools/labnb.py verify        # cited paths exist, evidence hashes still match
```

Before submitting anything for publication: run `verify`, make sure every claim used has grade A (or is labelled with its real grade), re-run the generating scripts from the recorded commit,
and check `CLAIMS.md` for anything REFUTED or OPEN that the text still leans on.
